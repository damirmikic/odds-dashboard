# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Xtip Monitor": a local dashboard comparing Pinnacle prematch odds (via the PinnWire API) with the public MerkurXtip offer, for football (top leagues, UEFA, a few second divisions) basketball (NBA, European and national leagues), tennis (ATP, WTA, Challenger, ITF), ice hockey (NHL, KHL, European leagues) and MMA (UFC and every other PinnWire promotion). `README.md` documents the user-facing behaviour in detail (comparison rules, line filtering, derived handicaps, PWA, request budget, basketball, tennis, hockey, MMA) — read it before changing comparison logic.

## Commands

```powershell
python -m pip install -r requirements.txt        # only dependency: requests
cd frontend; npm install; npm run build; cd ..   # builds into ../static/dashboard_build
python pinnwire_dashboard.py                     # serves http://127.0.0.1:8070 (--port, --no-browser, --host)
python -m unittest test_pinnwire_dashboard       # all tests
python -m unittest test_pinnwire_dashboard.ClassName.test_name   # single test
python -m pip install -r requirements-dev.txt; python -m ruff check .   # Python lint (ruff.toml)
cd frontend; npm run lint                        # ESLint: recommended + react-hooks rules-of-hooks / exhaustive-deps
```

`start.bat` / `start.sh` install deps, build and run. Frontend dev: run the Python server, then `npm run dev` in `frontend/` (Vite on 5175, proxies `/api` to 8070). Both linters pass with no suppressions except the commented `noqa` catch-alls; keep it that way (the hooks deps are listed fully, helper closures are `useCallback`). The Python server does not reload: restart it after backend changes. Deep links for checking UI: `/?sport=basketball|tennis|hockey|mma|value`, `&view=value|missing|compare`, `#<event id>`.

## Architecture

One Python process serves all five sports; each sport has its own PinnWire snapshot cache, MerkurXtip offer cache and comparison code, built on the shared pieces in `common.py`.

- `common.py` — what every sport shares: time helpers, `merge_event`, `SnapshotState` (API key, full/delta fetching with the hooks `incoming` / `merge` / `merged`, hourly full reload, the MerkurXtip offer cache, `record()` to the CLV and price history stores), `compare_row`, `value_items` and `best_edge` over `[(period key, compare row)]`, `team_ladders` and `param_lines` (MerkurXtip lines from `params`), and the untracked-league pairing behind every "Nedostaju" view (`unpaired_other`, `other_score`, `other_competitions`, `offered_other`). Pinnacle ladders are `pw.ladder` / `pw.ladder_limits`. Change shared behaviour here, not per sport. It must not import `pinnwire_dashboard`.

- `pinnwire_dashboard.py` — stdlib `http.server` app, **football**. `DashboardState` (a `common.SnapshotState`; its `merged` hook records opening prices) holds the event cache, and `History` (opening/previous 1X2 prices and the daily request counter, persisted to `data/dashboard_history.json`, shared by every sport state). `Handler` serves `/api/board`, `/api/match/<id>` and `/api/<sport>/board|match/<id>` through `SPORT_ROUTE` and `SPORT_STATES` (the one table of sport states, also used by drops and the CLV worker), plus the static bundle. `DashboardState.events` keeps every main fixture of the football feed, but only `COMPETITIONS` leagues are compared; the rest feeds only the "Nedostaju" view (`missing_other`: name + kickoff pairing against the whole MerkurXtip offer, cached, returned as `otherMissing` / `otherCompetitions`). `COMPETITIONS` (data only, in `football_competitions.py`; keyed by PinnWire `league_id`, with a `merkur` `leagueShort`) defines tracked leagues. To add a league, find its PinnWire `league_id` in a snapshot and the MerkurXtip `leagueShort` in the offer (names differ, e.g. PinnWire "Liga Pro" is MerkurXtip "Liga Profesional"), add the entry with a unique `key` and badge `code` (top league the bare country code, lower tiers `ENG2`…, cups `GERC`, youth `TURU19`, regional groups `AUT3W`; when the obvious code is taken, number the new one, e.g. `THA1` next to `THA`) and a `.comp-badge.<key>` colour in `dashboard.css` (a frontend change: rebuild, or `BuildSyncTests` fails); `CompetitionTableTests` checks uniqueness and colours for every sport. `merkur` may also be a numeric `leagueId` (no `leagueShort` in the offer); `merkur_also` adds further MerkurXtip leagues, `merkur_of` shares another entry's league; `HIDDEN_MISSING_LEAGUES` keeps PinnWire leagues out of "Nedostaju". The "Nedostaju" view lists unpaired leagues as `<PinnWire name> · N mečeva · PinnWire <league_id> · MerkurXtip <leagueShort> (<leagueId>)`, which is everything an entry needs. To check a league by hand: `merkur_client.MerkurAPI().offer()` rows carry `leagueShort`/`leagueId`/`leagueName`, `pinnwire_client.PinnWireAPI(key).prematch_snapshot()` events carry `league_id`/`league_name`. `compare_period`, `merkur_summary` and `goals_line` build the comparison served to the UI.
- `basketball.py` — **basketball**, independent of the football code (it must not import `pinnwire_dashboard`: run as a script that module is `__main__`, so importing it would create a second state). `BasketballState` (sport settings as class attributes: `competition_list`, `mx_comp`, `league_ids`, `score_fn`; `board_match` builds the board entry for basketball, tennis and hockey), the MerkurXtip code tables (`MX_PERIOD`), `compare()` per period (full game, 1st half; 1st quarter is decoded but PinnWire only quotes it close to the start), lines outside Pinnacle's ladder priced from a normal model (`model_probability`, flagged `modeled`), and the "Merkur kasni" check (`stale_gaps`: MerkurXtip main line ≥ 2 points from Pinnacle's). `COMPETITIONS` maps PinnWire `league_id` to the MerkurXtip numeric `leagueId` (`leagueShort` is not unique in basketball). The snapshot keeps every league; the `tracked` hook (league in `league_ids`; tennis and MMA track everything) splits the board, and `missing_other` pairs the rest like football (`otherMissing` / `otherCompetitions` / `otherOffered`, shown by the shared `OtherOffered` in `missing.jsx`). MerkurXtip can move a league to a new `leagueId` for a new season (FIBA Europe Cup did): when a whole league shows as "nije u ponudi", look up its `leagueId` in the live offer and add it as `mx_extra`.
- `tennis.py` — **tennis**, `TennisState` subclasses `BasketballState` (overriding its hook methods: `incoming`, `merge`, `complete`, `shape`, `pair`, `hints`, `offered`, `competitions`; it imports `basketball` for `board_match`, `board_cell` and event helpers). The Merkur feed is the same with letter `T`. PinnWire quotes tennis as a main event in sets plus a `parent_id` side event in games (`include_alt_units=1`), folded into one event under `games`. Competitions are tournaments derived from league names (league_id changes every round), pairing is by player names (`player_score`: surname plus initial) and a 12 h kickoff window with no competition check. Exact lines only, no model.
- `hockey.py` — **ice hockey**, `HockeyState` subclasses `BasketballState` and only sets its class attributes (`competition_list`, `mx_comp`, `league_ids`, `score_fn`) and the hooks `shape` and `drop_quotes`. The Merkur feed is the same with letter `H`. PinnWire period 0 is the game with overtime (two-way winner), 6 the 60 minutes (1X2, handicap, totals, team totals), 1–3 the thirds; the board winner is the OT winner, its handicap/total cells are the 60 minutes. `COMPETITIONS` maps PinnWire `league_id` to the MerkurXtip `leagueId`; pairing is competition + 3 h + names with hockey-only `ALIASES` (Merkur name → Pinnacle name). Exact half-point lines only, no AH 0 on purpose (PinnWire quotes one, but the Pinnacle two-way price is the OT moneyline), no model.
- `mma.py` — **MMA**, `MmaState` subclasses `BasketballState` (hooks `incoming`, `shape`, `pair`, `hints`, `offered`, `drop_quotes`, `competitions`). The Merkur feed letter is `MM`. PinnWire sport 8 quotes period 0 only: winner and total rounds ("Ukupno rundi", Merkur `params.our`); no handicap (`spreadTitle: null` hides the board columns). Every PinnWire MMA league is kept, the promotion is the competition (`PROMOTIONS` → badge class). Pairing is by fighter names (`tennis.player_score` plus `ALIASES`) and a 12 h window, no competition check; each Merkur row is offered in both fighter orders and a reversed pair carries `pinSwapped`, which `merkur_markets` and `shape_match` turn back to Pinnacle's order.
- `handball.py` — **handball and volleyball**, `HandballState` subclasses `BasketballState` (hooks `shape`, `pair`, `hints`, `offered`, `drop_quotes`, `tracked`, `complete`, `competitions`). PinnWire sport 10 holds both and `kind()` tells them apart by the totals (handball 20-99 goals, volleyball sets or 100+ points; no total yet means not shown). The Merkur offer is `JoinedAPI` over the `HB` and `V` feeds, each row has `sport`, which is also the pairing key. Handball compares winner/1X2, handicap and totals (`MX_PERIOD`), volleyball the winner only. Competitions are the PinnWire leagues (no Merkur league mapping), pairing is names + 3 h with `common.other_score` and a `W` marker for women's leagues. `owns()` filters the shared drop stream and the suspended list., devig and market parsing. `devig()` uses Shin for two-way markets and the power method for 1X2 (power overshoots on lopsided two-way prices). `allowed_line()` is the rule for which handicap/total lines are used (half-point lines only; football additionally keeps AH 0 ↔ draw-no-bet); basketball applies it to both books. `best_per_line_market()` is the Value-list rule shared by all sports: one outcome per match, period and line market (the largest edge), markets without a line keep every outcome.
- Drop alerts: `DropFeed` (started in `main()`) holds one SSE connection to PinnWire `/odds-drop-prematch` (`PinnWireAPI.drop_stream`, `recheck=DROP_RECHECK`, no REST requests) and buffers 3 h of drops (`normalize_drop` maps SSE names to the `/api/drops` ones). `/api/drops?sport=` (`drops_response`) serves them with the board match id and the MerkurXtip price of the same outcome from each state's `quotes` (built at every board from the compare rows via `quote_index`/`drop_key`; away spread drops carry the away line, tennis games drops come on the games side event, `games_id`). The UI polls it every 3 s (`useDropAlerts`).
- `clv.py` — closing line value store (SQLite, `data/clv.sqlite3`, opened by `start_clv()` in `main()` so tests never touch it). Each state's `board()` hands its compare rows to `ClvStore.observe()`: a first-seen outcome with `ev >= MIN_EV` becomes a signal, later boards of an unstarted match overwrite its `close_*` columns. `ClvWorker` in `pinnwire_dashboard.py` refreshes boards in the background (30 s, 10 s near kickoff) so closing lines exist without a browser; `/api/clv` and the Alerti → CLV page read it. It must not import `pinnwire_dashboard`.
- `price_history.py` — price history store (SQLite, `data/prices.sqlite3`, opened by `start_prices()` in `main()`). Each state's `board()` hands the same rows as the CLV store to `PriceStore.observe()`, which writes an outcome only when its Pinnacle, MerkurXtip or fair price changed, and `annotate()` adds `seenAt` / `pinChangedAt` / `mxChangedAt` to the value items. The last state is kept in memory and reloaded from the database after a restart; matches are pruned `KEEP_HOURS` after kickoff. `/api/history` feeds the sparklines and charts (`Sparkline`, `PriceChart`, `usePriceHistory` in `priceHistory.jsx`). It must not import `pinnwire_dashboard`.
- `value_marks.py` — value marks (SQLite, `data/marks.sqlite3`, opened by `start_marks()` in `main()`): the "Komentar trejdera" column of `ValueTable` (`marks.jsx`), shared by every user of the server via `GET`/`POST /api/marks`; keyed by an opaque string the UI builds (`markKey`: sport, match, period, group, line, outcome), with the MerkurXtip price at marking and the proxy's `X-Remote-User`. It must not import `pinnwire_dashboard`.
- `applog.py` — application log (`data/logs/app.log`, rotated, plus the console; `setup()` runs in `main()`, so tests never write it). Modules log to `xtip.*` loggers: state changes (failed, recovered), not every refresh, never prices or the API key. `common.SnapshotState._fetch_logged` and `merkur_offer`, `DropFeed.cycle`, `ClvWorker` and `Handler.internal_error` are the logging points.
- `merkur_client.py` — MerkurXtip offer client (`MerkurAPI(offer_path=...)`, football list ~7 MB cached 60 s), odds-code decoding for football (docstring documents the verified code mappings), and event pairing (competition + kickoff within 3 h (football 6 h, `PAIR_WINDOW`) + fuzzy team names: `name_score` averaged over home and away must reach 0.5; `ALIASES` maps a whole normalised name (lowercase ASCII, punctuation as spaces, e.g. `"union sg 2": "union saint gilloise ii"`) to the other book's form; add misses there with a `name_score` check in the name test). `hints()` (over `closest_unpaired()`) feeds the "Nedostaju" hints from the board's own pairing, so a board pairs once. `is_prematch()` matters: MerkurXtip flags matches `live` hours before kickoff, so only started matches may be dropped, never every `live` row.
- `frontend/dashboard/` — React 19 + Vite SPA, one module per area (each starts with a line saying what it holds): `App.jsx` (shell, football screen, API key panel), `football/board.jsx` and `football/detail.jsx`, `sport.jsx` (basketball, tennis, hockey and MMA: `SportPane`, `SportOddsModal`, boards loaded by `useSportBoard`; texts and market groups per sport in `sportViews.js`), `value.jsx`, `allValue.jsx` (the all-sports Value screen, `sport` "value": values of every board via `collectValues`), `missing.jsx`, `menu.jsx`, `priceHistory.jsx`, `alerts.jsx`, `clv.jsx`, `search.jsx` (team search across every loaded board), and the shared `api.js` (`requestJson`, localStorage), `hooks.js`, `format.js`, `ui.jsx`. All screens share `SideMenu` (sport icons with match counts, competitions grouped by country), `ValueTable`, `MissingTable` and the odds modal pattern. Views: compare, pinnacle (football only), value, missing ("Nedostaju"). All boards are loaded at startup so the sport icons can show counts. PWA files (manifest, `sw.js`, icons) live in `frontend/dashboard/public/`; bump `VERSION` in `sw.js` when caching rules change.
- `static/dashboard_build/` — **committed** production bundle served by Python. After frontend changes, run `npm run build` so the bundle stays in sync: the build writes `source-hash.txt` (a hash of `frontend/dashboard/`, `package.json`, `package-lock.json` and `vite.config.js`) and `BuildSyncTests` fails when the source no longer matches it.
- `deploy/` — server setup for a subdomain on Linux (systemd `xtip.service`, `install.sh`, `update.sh`, `Caddyfile` / `nginx.conf` with basic auth); the app itself has no login, so it stays on 127.0.0.1 behind the proxy. README "Server" has the steps.
- `data/` — runtime state (`dashboard_history.json`, `clv.sqlite3`, `prices.sqlite3`, `logs/`) and the API key (`pinnwire_config.json`, never share; `PINNWIRE_API_KEY` env overrides).

## Constraints

- "Max bet" is the Pinnacle limit (`max` of a spread/total line in PinnWire). The odds modals show it per market as `maxBet` on compare rows (`pinnacle_max` for football, `pinnacle_limits` in `basketball.py`/`tennis.py`/`hockey.py`); the 1X2 / moneyline carries no limit, and modelled lines have none. The board shows the main line's limit in green.
- The sport menu has football, basketball, tennis, hockey, MMA and "Rukomet i odbojka" (one board, `handball.py`); the standalone volleyball sport was removed on purpose, volleyball only lives there with its winner market.
- The user's PinnWire plan is Pro + Drops: 10 req/s REST, SSE drop streams, no raw WebSocket (paid add-on). Request count is no longer tight, but keep delta requests (`since=`) for refreshes; each sport costs one request per refresh (five sports, five requests) and the odds modals use only MerkurXtip single-match requests.
- UI strings are in Serbian (e.g. Osveži, Više/Manje, Nedostaju). Compare-row `group` labels ("Hendikep", "Ukupno golova", "Pobednik" …) double as identifiers: `DROP_GROUPS`, the CLV signature (`clv.signature`) and the price history key all use them, so renaming one splits CLV/history and breaks drop matching.
- Errors travel as exception types and `Handler` maps them: `PermissionError` → 401 (no or rejected API key), `LookupError` → 404 (match gone; `KeyError`/`IndexError` count as bugs → 500), `RuntimeError` → 502 (upstream failed), anything else → 500 with a traceback. The clients raise these deliberately; keep to them in new code.
- Concurrency: `ThreadingHTTPServer`, `ClvWorker` and `DropFeed` run boards and fetches in parallel, also for the same sport (UI refresh plus worker). Each state guards its snapshot with `lock`/`fetch_lock`; `History`, `ClvStore` and `PriceStore` take their own locks. Keep shared mutable state behind one of them.
- `POST /api/config` and `POST /api/marks` only accept `application/json` (a cross-site form cannot replace the API key).
- MerkurXtip code tables come from `https://www.merkurxtip.rs/restapi/offer/sr/ttg_lang` (`betPickMap` keys `<code>_<sport suffix>`, basketball `_B`/`_BB`, tennis `_T`, hockey `_H`, MMA `_MM`); verify a code against live data (EV should centre on about −MerkurXtip margin) before relying on it.
