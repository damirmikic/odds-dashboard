# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Xtip Monitor": a local dashboard comparing Pinnacle prematch odds (via the PinnWire API) with the public MerkurXtip offer, for football (top leagues, UEFA, a few second divisions) basketball (NBA, European and national leagues), tennis (ATP, WTA, Challenger, ITF) and ice hockey (NHL, KHL, European leagues). `README.md` documents the user-facing behaviour in detail (comparison rules, line filtering, derived handicaps, PWA, request budget, basketball, tennis, hockey) — read it before changing comparison logic.

## Commands

```powershell
python -m pip install -r requirements.txt        # only dependency: requests
cd frontend; npm install; npm run build; cd ..   # builds into ../static/dashboard_build
python pinnwire_dashboard.py                     # serves http://127.0.0.1:8070 (--port, --no-browser, --host)
python -m unittest test_pinnwire_dashboard       # all tests
python -m unittest test_pinnwire_dashboard.ClassName.test_name   # single test
```

`start.bat` / `start.sh` install deps, build and run. Frontend dev: run the Python server, then `npm run dev` in `frontend/` (Vite on 5175, proxies `/api` to 8070). No linter is configured. The Python server does not reload: restart it after backend changes. Deep links for checking UI: `/?sport=basketball|tennis|hockey`, `&view=value|missing|compare`, `#<event id>`.

## Architecture

One Python process serves all four sports; each sport has its own PinnWire snapshot cache, MerkurXtip offer cache and comparison code, built on the shared pieces in `common.py`.

- `common.py` — what every sport shares: time helpers, `merge_event`, `SnapshotState` (API key, full/delta fetching with the hooks `incoming` / `merge` / `merged`, hourly full reload, the MerkurXtip offer cache, `record()` to the CLV and price history stores), `compare_row`, `value_items` and `best_edge` over `[(period key, compare row)]`, `team_ladders` and `param_lines` (MerkurXtip lines from `params`). Pinnacle ladders are `pw.ladder` / `pw.ladder_limits`. Change shared behaviour here, not per sport. It must not import `pinnwire_dashboard`.

- `pinnwire_dashboard.py` — stdlib `http.server` app, **football**. `DashboardState` (a `common.SnapshotState`; its `merged` hook records opening prices) holds the event cache, and `History` (opening/previous 1X2 prices and the daily request counter, persisted to `data/dashboard_history.json`, shared with basketball). `Handler` serves `/api/board`, `/api/match/<id>` and `/api/<sport>/board|match/<id>` through `SPORT_ROUTE` and `SPORT_STATES` (the one table of sport states, also used by drops and the CLV worker), plus the static bundle. `DashboardState.events` keeps every main fixture of the football feed, but only `COMPETITIONS` leagues are compared; the rest feeds only the "Nedostaju" view (`missing_other`: name + kickoff pairing against the whole MerkurXtip offer, cached, returned as `otherMissing` / `otherCompetitions`). `COMPETITIONS` (data only, in `football_competitions.py`; keyed by PinnWire `league_id`, with a `merkur` `leagueShort`) defines tracked leagues. To add a league, find its PinnWire `league_id` in a snapshot and the MerkurXtip `leagueShort` in the offer (names differ, e.g. PinnWire "Liga Pro" is MerkurXtip "Liga Profesional"), add the entry with a unique `key` and badge `code` (top league the bare country code, lower tiers `ENG2`…, cups `GERC`) and a `.comp-badge.<key>` colour in `dashboard.css`; `CompetitionTableTests` checks uniqueness and colours for every sport. The `compare_*` / `value_items` / `best_edge` / `goals_line` functions build the comparison served to the UI.
- `basketball.py` — **basketball**, independent of the football code (it must not import `pinnwire_dashboard`: run as a script that module is `__main__`, so importing it would create a second state). `BasketballState` (sport settings as class attributes: `competition_list`, `mx_comp`, `league_ids`, `score_fn`; `board_match` builds the board entry for basketball, tennis and hockey), the MerkurXtip code tables (`MX_PERIOD`), `compare()` per period (full game, 1st half; 1st quarter is decoded but PinnWire only quotes it close to the start), lines outside Pinnacle's ladder priced from a normal model (`model_probability`, flagged `modeled`), and the "Merkur kasni" check (`stale_gaps`: MerkurXtip main line ≥ 2 points from Pinnacle's). `COMPETITIONS` maps PinnWire `league_id` to the MerkurXtip numeric `leagueId` (`leagueShort` is not unique in basketball). MerkurXtip can move a league to a new `leagueId` for a new season (FIBA Europe Cup did): when a whole league shows as "nije u ponudi", look up its `leagueId` in the live offer and add it as `mx_extra`.
- `tennis.py` — **tennis**, `TennisState` subclasses `BasketballState` (overriding its hook methods: `incoming`, `merge`, `complete`, `shape`, `pair`, `hints`, `offered`, `competitions`; it imports `basketball` for `board_match`, `board_cell` and event helpers). The Merkur feed is the same with letter `T`. PinnWire quotes tennis as a main event in sets plus a `parent_id` side event in games (`include_alt_units=1`), folded into one event under `games`. Competitions are tournaments derived from league names (league_id changes every round), pairing is by player names (`player_score`: surname plus initial) and a 12 h kickoff window with no competition check. Exact lines only, no model.
- `hockey.py` — **ice hockey**, `HockeyState` subclasses `BasketballState` and only sets its class attributes (`competition_list`, `mx_comp`, `league_ids`, `score_fn`) and the hooks `shape` and `drop_quotes`. The Merkur feed is the same with letter `H`. PinnWire period 0 is the game with overtime (two-way winner), 6 the 60 minutes (1X2, handicap incl. AH 0, totals, team totals), 1–3 the thirds; the board winner is the OT winner, its handicap/total cells are the 60 minutes. `COMPETITIONS` maps PinnWire `league_id` to the MerkurXtip `leagueId`; pairing is competition + 3 h + names with hockey-only `ALIASES` (Merkur name → Pinnacle name). Exact lines only, no model.
- `pinnwire_client.py` — PinnWire REST client, devig and market parsing. `devig()` uses Shin for two-way markets and the power method for 1X2 (power overshoots on lopsided two-way prices). `allowed_line()` is the rule for which handicap/total lines are used (half-point lines only; football additionally keeps AH 0 ↔ draw-no-bet); basketball applies it to both books. `best_per_line_market()` is the Value-list rule shared by all sports: one outcome per match, period and line market (the largest edge), markets without a line keep every outcome.
- Drop alerts: `DropFeed` (started in `main()`) holds one SSE connection to PinnWire `/odds-drop-prematch` (`PinnWireAPI.drop_stream`, `recheck=DROP_RECHECK`, no REST requests) and buffers 3 h of drops (`normalize_drop` maps SSE names to the `/api/drops` ones). `/api/drops?sport=` (`drops_response`) serves them with the board match id and the MerkurXtip price of the same outcome from each state's `quotes` (built at every board from the compare rows via `quote_index`/`drop_key`; away spread drops carry the away line, tennis games drops come on the games side event, `games_id`). The UI polls it every 3 s (`useDropAlerts`).
- `clv.py` — closing line value store (SQLite, `data/clv.sqlite3`, opened by `start_clv()` in `main()` so tests never touch it). Each state's `board()` hands its compare rows to `ClvStore.observe()`: a first-seen outcome with `ev >= MIN_EV` becomes a signal, later boards of an unstarted match overwrite its `close_*` columns. `ClvWorker` in `pinnwire_dashboard.py` refreshes boards in the background (30 s, 10 s near kickoff) so closing lines exist without a browser; `/api/clv` and the Alerti → CLV page read it. It must not import `pinnwire_dashboard`.
- `price_history.py` — price history store (SQLite, `data/prices.sqlite3`, opened by `start_prices()` in `main()`). Each state's `board()` hands the same rows as the CLV store to `PriceStore.observe()`, which writes an outcome only when its Pinnacle, MerkurXtip or fair price changed, and `annotate()` adds `seenAt` / `pinChangedAt` / `mxChangedAt` to the value items. The last state is kept in memory and reloaded from the database after a restart; matches are pruned `KEEP_HOURS` after kickoff. `/api/history` feeds the sparklines and charts (`Sparkline`, `PriceChart`, `usePriceHistory` in `priceHistory.jsx`). It must not import `pinnwire_dashboard`.
- `merkur_client.py` — MerkurXtip offer client (`MerkurAPI(offer_path=...)`, football list ~7 MB cached 60 s), odds-code decoding for football (docstring documents the verified code mappings), and event pairing (competition + kickoff within 3 h (football 6 h, `PAIR_WINDOW`) + fuzzy team names; add misses to `ALIASES`). `closest_unpaired()` feeds the "Nedostaju" hints. `is_prematch()` matters: MerkurXtip flags matches `live` hours before kickoff, so only started matches may be dropped, never every `live` row.
- `frontend/dashboard/` — React 19 + Vite SPA, one module per area (each starts with a line saying what it holds): `App.jsx` (shell, football screen, API key panel), `football/board.jsx` and `football/detail.jsx`, `sport.jsx` (basketball, tennis and hockey: `SportPane`, `SportOddsModal`, boards loaded by `useSportBoard`; texts and market groups per sport in `sportViews.js`), `value.jsx`, `missing.jsx`, `menu.jsx`, `priceHistory.jsx`, `alerts.jsx`, `clv.jsx`, and the shared `api.js` (`requestJson`, localStorage), `hooks.js`, `format.js`, `ui.jsx`. All screens share `SideMenu` (sport icons with match counts, competitions grouped by country), `ValueTable`, `MissingTable` and the odds modal pattern. Views: compare, pinnacle (football only), value, missing ("Nedostaju"). All boards are loaded at startup so the sport icons can show counts. PWA files (manifest, `sw.js`, icons) live in `frontend/dashboard/public/`; bump `VERSION` in `sw.js` when caching rules change.
- `static/dashboard_build/` — **committed** production bundle served by Python. After frontend changes, run `npm run build` so the bundle stays in sync: the build writes `source-hash.txt` (a hash of `frontend/dashboard/`, `package.json`, `package-lock.json` and `vite.config.js`) and `BuildSyncTests` fails when the source no longer matches it.
- `data/` — runtime state (`dashboard_history.json`, `clv.sqlite3`, `prices.sqlite3`) and the API key (`pinnwire_config.json`, never share; `PINNWIRE_API_KEY` env overrides).

## Constraints

- "Max bet" is the Pinnacle limit (`max` of a spread/total line in PinnWire). The odds modals show it per market as `maxBet` on compare rows (`pinnacle_max` for football, `pinnacle_limits` in `basketball.py`/`tennis.py`/`hockey.py`); the 1X2 / moneyline carries no limit, and modelled lines have none. The board shows the main line's limit in green.
- The sport menu has football, basketball, tennis and hockey; volleyball was removed on purpose.
- The user's PinnWire plan is Pro + Drops: 10 req/s REST, SSE drop streams, no raw WebSocket (paid add-on). Request count is no longer tight, but keep delta requests (`since=`) for refreshes; each sport costs one request per refresh (four sports, four requests) and the odds modals use only MerkurXtip single-match requests.
- UI strings are in Serbian (e.g. Osveži, Više/Manje, Nedostaju).
- MerkurXtip code tables come from `https://www.merkurxtip.rs/restapi/offer/sr/ttg_lang` (`betPickMap` keys `<code>_<sport suffix>`, basketball `_B`/`_BB`, tennis `_T`, hockey `_H`); verify a code against live data (EV should centre on about −MerkurXtip margin) before relying on it.
